Q1

แยกร้านทำงานยังไง — ทำไมไม่ให้ AI ทำ?

▸

“AI อ่านชื่อร้านดิบ — server ตัดสิน identity แบบ deterministic (พิสูจน์ได้ ไม่ใช่เดา)”

  • กลไก — AI คืน merchant (raw) → server normalize → match Store master (exact → RapidFuzz) → เจอ = Visit · ไม่เจอ = Unknown-store ให้คนยืนยัน
  • ทำไม deterministic — store_id คือ key ของ aggregate ผิดทีเดียวยอดทั้งเดือนเพี้ยน → ต้องนิ่ง
  • ตรวจสอบได้ — ตอบได้ว่า “ไปร้าน #42 เพราะ fuzzy 0.91 ≥ 0.85” · Unknown-store = human gate กัน store ผี
Q2

ทำไมไม่ให้ AI ส่ง unit หรือฉีด Store master ให้จับเอง?

▸

“AI ทำแค่ perception (อ่าน) — ค่าที่ derive/match ได้ ให้ server (หลักเดียวกับ Q1)”

  • unit — เป็นคุณสมบัติของ SKU (ขายเป็น ลัง/ถาด) ไม่ใช่สิ่งที่เขียน → รู้ code ก็รู้ unit (override) · นอก catalog ใช้ที่ AI อ่าน · ส่วน qty เชื่อ AI เพราะคือสิ่งที่เขียนจริง
  • ฉีด catalog แต่ไม่ฉีด Store master — catalog เซตเล็ก/นิ่ง cache ได้ · Store master พันร้านโตเรื่อยๆ ฉีดทุกใบเปลือง + ถ้า AI เลือกจาก list จะเลือกตัวใกล้สุดเสมอ เสีย threshold gate
  • หลักรวม — เชื่อ AI น้อย field = ผิดน้อย · server lookup ฟรี/เร็ว
Q3

เรื่อง scale ล่ะ?

▸

“workload เป็น batch รายเดือน (ไม่ใช่ high-QPS) — scale lever อยู่ใน stack แล้ว”

  • Workload — ~30k ใบ/เดือน ≈ 1k/วัน · พีค = burst ปลายเดือน · คอขวดคือ LLM call → scale = process ขนานมากขึ้น
  • Lever พร้อม — arq + Redis เพิ่ม worker แนวนอน · FastAPI stateless → scale หลัง LB
  • DB — SQLite พอ · SQLAlchemy → ย้าย Postgres แค่เปลี่ยน connection string

เพดานจริง = rate limit OpenRouter (backoff + queue) · SSE in-process — multi-instance ย้ายไป Redis pub/sub

Q4

ทำไมไม่ใช้ OCR?

▸

“เทสต์จริงแล้ว OCR ไม่เพิ่ม accuracy แต่ช้ากว่า ~4× บนใบเสร็จไทย”

  • ปัญหาเราไม่ใช่ “ถอดตัวอักษร” แต่คือ “เข้าใจว่าตัวย่อ = SKU ไหน” — OCR ให้แค่ข้อความดิบ สุดท้ายยังต้องมี LLM มาแปลความอยู่ดี
  • OCR ลายมือ/ตัวย่อไทยพัง (สิงห์, ส., x2) → กลายเป็น 2 จุดที่ error สะสม
  • Vision LLM อ่าน + จับคู่ catalog ในคอลเดียว = perception + understanding พร้อมกัน · 1 จุดพัง · เร็วกว่า

Benchmark จริง: PaddleOCR + Gemini vs Gemini อย่างเดียว → accuracy เท่ากัน แต่ OCR ช้ากว่า ~4× → ตัด OCR ทิ้ง

Q5

ฉีด catalog ทุก call ไม่แพง/ไม่ช้าเหรอ?

▸

“catalog เป็น prefix นิ่ง → prompt cache ลดราคา ไม่ได้จ่ายเต็มซ้ำทุกใบ”

  • จัด prompt มาเพื่อ cache — [system] catalog+schema (นิ่ง → cache prefix) · [user] รูป+task (เปลี่ยนทุกใบ อยู่ท้าย)
  • ลดราคา ไม่ใช่ฟรี — call แรกเขียน cache (จ่ายเต็ม) · ถัดไปใน ~5 นาที hit → prefix เหลือ ~10% · คุ้มสุดตอน batch
  • วัดจริง — ~$0.002/ใบ ตอน batch (cold ~$0.005)

บนเวทีอย่าพูด “ฟรี” — พูดว่า “prefix ถูก cache ลดราคา”
