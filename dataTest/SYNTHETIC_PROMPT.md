# Synthetic Receipt Prompt

ใช้ AI image generation (Gemini 3 Image / GPT-4o image / Imagen) สร้างใบเสร็จทดสอบให้ครอบคลุม fraud types, clustering, OCR challenges, และ catalog matching — รวม 9 cases (10 ใบ)

> ⚠️ **ตัด case ออกแล้ว 2 รายการ** เพราะ image-gen ไม่ทำให้ story trigger ตามตั้งใจ:
> - **Duplicate-pair** — Gemini วาดยอด 2 ใบไม่เท่ากัน duplicate detection ไม่ trigger
> - **Date-thai-wrong** — AI extraction ฉลาดเกินไป แปลง "พ.ศ. 68" → "2025" อัตโนมัติ ไม่ flag เป็น parse error

---

## วิธีใช้

1. Copy **Master Prompt** ด้านล่าง (block แรก) เป็น context
2. Append **Case Variant** (1 ใน 10 cases) ที่ต้องการ
3. ส่งให้ AI สร้างภาพ → save เป็น `dataTest/demo/<NN>.jpeg` ตาม sequential numbering
4. รัน `scripts/pitching_test.py` หรือ upload ผ่าน UI → เช็คผลใน Review/Dashboard

แนะนำ:

- **Gemini 3 Image** — รองรับภาษาไทยดีสุด, ตัวเลข/ตารางคมชัด
- **GPT-4o image** — ใช้ได้ แต่ตัวอักษรไทยบางครั้งเพี้ยน
- ถ้า text เพี้ยน → re-generate หรือ post-edit ใน Photoshop/Figma แค่บางจุด

## Master Prompt (วางก่อนทุก case)

```
สร้างภาพ "ใบเสร็จ/ใบกำกับภาษี/บิลเงินสด" ของร้านค้าส่งในไทย ที่ดูเหมือนถ่ายมาจากกล้องมือถือจริง — ใช้ทดสอบระบบ AI ที่อ่านใบเสร็จ

ข้อกำหนดทั่วไป:
- ภาษาไทยเป็นหลัก ตัวเลขอารบิค
- รวมข้อมูล: ชื่อร้าน, ที่อยู่/เบอร์โทร, เลขที่บิล, วันที่, รายการสินค้า (ชื่อ/จำนวน/ราคาต่อหน่วย/ยอด), ยอดรวม, VAT 7% (ถ้าเป็นใบกำกับภาษี), ยอดสุทธิ
- ขนาดภาพ ~1000x1500px, มุมเอียงเล็กน้อย, มีเงาหรือพับนิดหน่อย, พื้นหลังโต๊ะไม้/พื้นกระเบื้อง

Catalog สินค้าให้สุ่มจาก (ใส่ตามจริงเพราะระบบจะ match):
- เบียร์: เบียร์สิงห์ขวดใหญ่, เบียร์ลีโอขวดใหญ่/ขวดเล็ก, เบียร์อาซาฮีกระป๋อง, เบียร์สิงห์กระป๋อง
- น้ำดื่ม: น้ำสิงห์เพ็ท 600ml / 1.5L, น้ำแร่ฟิจิ 500ml
- โซดา: โซดาสิงห์, สิงห์เลมอนโซดา (ปกติ/รสแตงโม/ครีม)
- สุรา/วิสกี้: บรั่นดีรีเจนซี่, สุราหงส์ทอง, สุราเบลนด์ 285, จอห์นนี่ วอล์คเกอร์ เรด, วิสกี้ซิลเวอร์วูล์ฟ ขวดแบน
- ชา: อิชิตัน ต้นตำรับ, ชาเขียวฮารุ
- พรีเมียม: เสื้อยืดลีโอสุพรีม L, แก้วเก็บความเย็น Snowy Journey

ชื่อร้านสุ่มจาก: รวยสุรา, ณ บวร เทรดดิ้ง, ลิ้มเฮงพัฒนา, สิงห์ สามารถ เทรดดิ้ง, จำปิสโตร์, กวงเสิน, สุดาพาณิชย์, ป้าเนเจอร์, มิตรราชบุรีเทรดดิ้ง, CSB, โจวบุ่งใช้, ประสงค์การค้าแพร่
```

## Case Variants (10 cases, 13 ใบ)

### 1. Happy-path-mixed (1 ใบ)

> สร้าง **ใบกำกับภาษี** ร้าน "รวยสุรา" จำนวน 3-4 รายการ ผสมเบียร์ + น้ำดื่ม + โซดา ยอดรวม ~฿8,000 VAT 7% คำนวณถูกต้อง พิมพ์คมชัด มุมเอียงเล็กน้อย

### 2. Multi-category-large (1 ใบ)

> สร้าง **ใบกำกับภาษี** ร้าน "ลิ้มเฮงพัฒนา" 12-15 รายการ ผสม 5 หมวด: เบียร์ + สุรา + วิสกี้ + น้ำ + โซดา ยอดรวม ~฿450,000 มีรายการเยอะ ตัวอักษรเล็ก ตารางยาว

### 3. Same-merchant cluster (3 ใบ — สร้าง 3 ครั้ง)

> ใบ A: ร้าน "**รวยสุรา**" เลขบิล A001 วันที่ 2025-12-01 ยอด ฿7,500 (เบียร์สิงห์ + ลีโอ)
>
> ใบ B: ร้าน "**รวย-สุรา**" (มีขีด) เลขบิล A042 วันที่ 2025-12-15 ยอด ฿47,245 (เบียร์ขวดใหญ่หลายลัง)
>
> ใบ C: ร้าน "**ร้าน รวยสุรา**" (มีคำว่า "ร้าน") เลขบิล A089 วันที่ 2026-01-08 ยอด ฿7,895 (เบียร์ + โซดา)
>
> *ทดสอบ merchant normalization clustering — 3 ใบควร group เป็นร้านเดียวกัน*

### 4. VAT-mismatch (1 ใบ)

> สร้าง **ใบกำกับภาษี** ร้าน "จำปิสโตร์" ที่ subtotal ฿10,000 แต่ VAT ที่พิมพ์เป็น **฿850** (จริงต้อง ฿700) และ grand_total = ฿10,850 — ตัวเลขผิดโดยเจตนา ทดสอบ fraud type `vat_mismatch`

### 5. Items-total-mismatch (1 ใบ)

> สร้าง **ใบกำกับภาษี** ร้าน "ณ บวร เทรดดิ้ง" 8-10 รายการ ที่ผลรวมราคารายการจริง ~฿37,000 แต่ grand_total พิมพ์เป็น **฿203,210** (ห่างกัน 80%+) — ดูเหมือนใบจริงแต่ตัวเลขรวมไม่ตรง ทดสอบ `items_total_mismatch`

### 6. Unusual-amount (1 ใบ)

> สร้าง **ใบกำกับภาษี** ร้าน "สุดาพาณิชย์" ยอด **฿850,000** (ปกติร้านนี้ออกบิลเฉลี่ย ~฿5,000-30,000) — ทดสอบ `unusual_amount` anomaly เทียบประวัติร้าน *(หมายเหตุ: ต้อง upload ใบ baseline ของร้านเดียวกัน 2-3 ใบก่อน flag ถึง trigger)*

### 7. Handwritten-spirit (1 ใบ)

> สร้าง **บิลเงินสดเขียนมือ** ลายมือไทยบนกระดาษเส้นบรรทัด ร้าน "ป้าเนเจอร์" 8-10 รายการ เน้นสุรา/วิสกี้: หงส์ทอง, เบลนด์ 285, JW Red, ลีโอ, สิงห์ ยอด ~฿30,000 — ทดสอบ OCR ลายมือ + catalog match สุรา

### 8. Low-quality-combo (1 ใบ)

> สร้าง **ใบเสร็จกระดาษความร้อน** ที่:
> - สีจางเลือนรางบางส่วน (faded thermal print)
> - มีรอยพับ/ยับ ทับตัวเลขบางจุด (crumpled)
> - ภาพเอียง 30-45° (rotated)
> ร้านอะไรก็ได้ 5-6 รายการ ฿12,000
>
> *ทดสอบ OCR robustness — AI ควรให้ confidence ต่ำ < 0.6*

### 9. Sales-report-non-receipt (1 ใบ)

> สร้างเอกสาร **"รายงานสรุปยอดขายรายเดือน"** หรือ "รายงานยอดขายแยกตามลูกค้า" รูปแบบตาราง — ไม่ใช่ใบเสร็จ มีคอลัมน์: ลูกค้า, ยอดขาย, จำนวน, vol — รวมรายการ catalog ของบุญรอด แต่ format เป็น report
>
> *ทดสอบ AI judgment: ระบบควร flag `ai_analysis: ไม่ใช่ใบเสร็จรับเงิน` risk low แต่ยังดึง catalog items ได้*

## Filename convention

ตั้งชื่อไฟล์เป็น `<NN>_<slug>.jpeg` ใน `dataTest/demo/` เช่น:

```
16_vat_mismatch.jpeg
17_items_mismatch.jpeg
18_duplicate_a.jpeg
19_duplicate_b.jpeg
20_unusual_amount.jpeg
21_date_buddhist_wrong.jpeg
22_handwritten_spirit.jpeg
23_low_quality.jpeg
24_sales_report.pdf
```

หรือใช้ sequential `12.jpeg`, `13.jpeg`, ... ตามแบบเดิม แล้วอัปเดต README ว่าแต่ละไฟล์โชว์อะไร
